1. Summary

Twelve deployed contracts were in scope, with about 1,750 lines of Kyte code (excluding comments). The review found 0 critical, 0 high, 0 medium, 5 low and 5 informational issues.

The core option escrow is sound. Collateral can only go to its seller or to the option holder. Exits keep working while the protocol is paused. Every entry point is protected against reentrancy, and fees are capped in code.

The five low findings cover:

  • the on-chain buyback route, which is not in use (buybacks are currently executed manually)
  • a griefing case on the ETH convenience Router, which has a direct-WETH fallback
  • a timelock delay that differs from the code comments
  • the dependency of physical settlement on token transferability

None of them allows anyone to take escrowed collateral or staked $KYTE.

2. System overview

Kyte is a fully collateralised options market:

  • A seller escrows the full collateral for a covered call (the token) or a cash-secured put (WETH strike).
  • A buyer pays the premium and receives an ERC-721 that represents the option.
  • The holder of that NFT can exercise before expiry.
  • After expiry anyone can return unexercised collateral to the seller.
  • Fees flow to a vault that splits them each epoch between stakers, buyback and operations.

Settings sit behind a timelock, and a guardian can only pause new exposure.

6. Methodology

  1. Source. Verified sources and compiler settings were downloaded from Sourcify for every address, keeping original file paths. Contracts were analysed one at a time, because live contracts come from different commits (KYT-10).
  2. Static analysis.
    • Slither 0.11.4 (Trail of Bits, 100 detectors) and Aderyn 0.6.8 (Cyfrin) were run on each contract.
    • The compiler settings matched each deployment: solc 0.8.28 or 0.8.26, via-IR, 200 optimiser runs, EVM version cancun.
  3. Manual review. Every tool result was read against the code and classified as a finding, accepted design, or a false positive. Escrow, buy, exercise, expiry, cancellation, fees, staking, buyback and governance paths were reviewed line by line (section 9).
  4. On-chain verification. Live settings, roles, balances and pool state were read at block 109,974,684 through a public Robinhood Chain RPC (sections 4 and 5).

7. Severity definitions

CriticalDirect loss or permanent freezing of user funds, with no special conditions.
HighLoss of user funds or insolvency under realistic conditions.
MediumLoss of funds under specific conditions, or a lasting break of a core function.
LowLimited impact, conditions that are unlikely or inactive, or an auxiliary path with a working alternative.
InformationalBest practice, documentation or design notes, with no direct impact.

Severity weighs impact against likelihood. A path that is not in use is rated by its current exposure, and the rating it would carry if enabled is stated in the finding.

8. Findings

Low KYT-01Acknowledged

The on-chain buyback route points to an unfunded pool (route not in use)

BuybackBurner 0x8a9d…fb95 · UniswapV4Adapter 0xfa17…dda6 · KyteHook pool 0x9689…1752

BuybackBurner.buyAndBurn swaps through UniswapV4Adapter, which trades in the KyteHook $KYTE/WETH pool (fee 0.30%, tick spacing 60). At block 109,974,684 that pool holds zero liquidity. Its spot price and its 10-minute TWAP both read 997,000 KYTE per WETH, which is its initialisation price less the LP fee. $KYTE's live market is a different Uniswap v4 pool (0xe25a…229e), where 1 WETH buys about 33.8 million KYTE.

Context. Kyte currently executes $KYTE buybacks manually. Platform volume has not yet justified automated buybacks, and BuybackBurner has never been called: no WETH has been swapped and lastPrice is 0. The rating reflects that this path is inactive. The same issue would be rated Medium if the path were switched on unchanged.

Impact if enabled. With no liquidity, a buyback call simply reverts. If liquidity were later added to the KyteHook pool near its current price, the on-chain slippage floors would accept a fill far above market. That is because the adapter quote is taken from the same pool. The keeper's minTokenOut would then be the only protection.

Recommendation. Before automated buybacks are switched on, point the burner at an adapter for the live pool (setAdapter, through the timelock), or seed the KyteHook pool at market price and let a TWAP history build. Derive minTokenOut from the live market.

Team response. Buybacks remain manual. The route will be corrected before automated buybacks are enabled.

Low KYT-02Acknowledged

The on-chain buyback price floor follows the last fill (route not in use)

BuybackBurner 0x8a9d…fb95, buyAndBurn lines 90–93 and 102

After each swap the burner records lastPrice, the tokens received per WETH. Every later call must satisfy minTokenOut ≥ wethIn × lastPrice × (1 − maxSlippageBps). If $KYTE rises in price by more than maxSlippageBps (5% now, 20% at most) between two buybacks, the next call reverts. lastPrice cannot be reset, and WETH in the burner can only leave through a swap.

Context. Kyte currently executes $KYTE buybacks manually. Platform volume has not yet justified automated buybacks, and BuybackBurner has never been called: no WETH has been swapped and lastPrice is 0. The rating reflects that this path is inactive. The same issue would be rated Medium if the path were switched on unchanged.

Recommendation. Before enabling automated buybacks, bound each fill against the TWAP only, use a floor that decays over time, or add a timelock-only reset. Then deploy the revised burner and point FeeVault.setDestinations at it.

Team response. Acknowledged. Buybacks remain manual and will move to a revised burner before automation is enabled.

Low KYT-03Acknowledged

The Router can be blocked by sending it 1 wei of WETH (direct market access unaffected)

Router 0xdD76…DF68, _finish line 77

After every call the Router requires its WETH and ETH balances to be exactly zero. Anyone can transfer WETH to it, and ETH can be forced in with SELFDESTRUCT. The Router has no sweep function and is immutable. A 1-wei transfer would therefore make buyWithETH, exerciseWithETH, buyPutWithETH and createPutOfferWithETH revert.

Impact. This affects availability only. No funds can be taken, and positions are unaffected. The markets remain usable directly with WETH (buy, exercise, exercisePut, createPutOffer). The timelock can install a replacement Router with setRouter on both markets. Both of the Router's balances are 0 at block 109,974,684.

Recommendation. In the next Router, compare against balances recorded at the start of each call, or forward any surplus to the FeeVault.

Team response. Acknowledged. Direct WETH access and a timelock replacement are the fallback; the fix is planned for the next Router.

Low KYT-04Acknowledged

The timelock delay is 10 minutes on chain; the code comments describe 48 hours

TimelockController 0xf8e6…2893 · Governed.sol line 7

getMinDelay() returns 600 seconds. The NatSpec in Governed.sol describes "the timelock (48 h, behind the admin Safe)". The timelock's powers are listed in section 4; none of them can move escrowed collateral or staked $KYTE. A short delay gives users less time to react to a settings change, such as new FeeVault destinations.

Recommendation. Either raise the delay with updateDelay (called through the timelock), or align the documentation with the value actually in use.

Team response. Acknowledged. The documentation will state the on-chain delay, and the delay will be reviewed as usage grows.

Low KYT-05Acknowledged

Physical settlement depends on the underlying token staying transferable

CallMarket _exercise · PutMarket exercisePut · OptionMarketBase _returnCollateral

Exercise moves the underlying token itself: a call delivers it to the holder, and a put pulls it from the holder. Expiry and cancellation return it to the seller. If a token's issuer paused or restricted transfers, those calls would revert. A pause that overlaps an option's expiry could cost the holder the exercise window. This is inherent to physical settlement and is not a code defect.

Recommendation. Explain this in the interface next to the session warnings. A trading halt is not the same as a token transfer pause.

Informational KYT-06Acknowledged

The guardian Safe needs a single signature

Guardian 0x9f43…0ef0

The guardian is a Safe with 3 owners and a threshold of 1. It can only pause and switch listings off, never unpause, enable anything or move funds. A single signer suits a fast circuit breaker.

Informational KYT-07Acknowledged

StakingPool.notifyReward emits no event

StakingPool notifyReward line 117

The reward amount is recorded by FeeVault.FeesSplit in the same transaction, so indexers can still follow it.

Informational KYT-08Acknowledged

KyteHaltGate reverts instead of answering if the oracle reports a future timestamp

HarmonicHaltGate gateVerdict line 81

If a row's writtenAt were ever in the future, uint64(block.timestamp) - writtenAt would underflow. That revert happens inside the try success block, so catch does not handle it. The behaviour fails closed. No live contract calls the gate.

Informational KYT-09Acknowledged

Rebasing tokens would break collateral accounting

OptionMarketBase locked / exposure

Fee-on-transfer tokens are rejected on chain. A rebasing token would make locked disagree with the real balance. Every listing goes through the timelock (251 tokens listed), and that curation is the control.

Informational KYT-10Acknowledged

Live contracts were built from different commits

Router · StakingPool · AssetRegistry

The markets use the newest constants (option ID tags 5 and 6, confirmed on chain). AssetRegistry uses an intermediate set, and Router and StakingPool were built from an earlier commit. Each contract was verified and analysed on its own source. The differences are only in constants those contracts do not use. Tagging one release commit per deployment would make future reviews simpler.

9. Contract review notes

OptionMarketBase · CallMarket · PutMarket

Offer creation validates the asset, amount, strike floor, minimum premium, duration (1 hour to 90 days), offer deadline, exposure cap and the per-seller open-offer limit, and then pulls the exact collateral. A buy sets Filled before minting the NFT and moving the premium. Exercise requires the NFT holder before expiry. Expiry is open to anyone at or after expiry and returns collateral to the seller. Cancellation is allowed for the seller only while the offer is open. The status always moves to its final value before any transfer, and every entry point is nonReentrant. Fees are fixed per position when it opens. The only places collateral can go are the seller and the option holder.

Router

The Router is stateless. It wraps exactly the ETH needed, calls the market for msg.sender and refunds the rest to msg.sender. The markets accept *For calls only from the router the timelock set, and exerciseFor still checks NFT ownership. The one issue found is KYT-03.

OptionNFT

Each ID carries a market tag in its top byte, and only that market can mint or burn it. The NFT uses _mint, not _safeMint, so a buyer cannot re-enter. tokenURI builds the metadata on chain and only embeds alphanumeric symbols, so a token symbol cannot inject JSON or SVG.

AssetRegistry

Only the timelock can list a token, enable it or enable puts. The guardian can only switch them off. Puts need both flags. Listing is capped at 300 tokens, and caps and minimum strikes apply per market.

FeeVault

Anyone can call split, at most once per epoch, and it works while paused. The split must sum to 100% and stakers always get at least 20% (live: 30% / 20% / 50%). Rounding dust stays for the next split. Destinations are set by the timelock.

StakingPool

Rewards use a reward-per-share accumulator with 1e36 precision. New stake waits until the next epoch and is then locked for one full epoch, which prevents just-in-time reward capture. Unstaking takes pending stake first, and both unstake and claim work while paused. Rewards that arrive with no active stake are carried forward. Fee-on-transfer stake tokens are rejected.

BuybackBurner · UniswapV4Adapter · KyteHook

The burner can only swap WETH for $KYTE and burn the output, falling back to the dead address if burning fails. Calls are limited to the keeper and bounded per call. KyteHook records a 128-slot tick ring buffer for its TWAP and takes its protocol fee in WETH only. This path is not in use: see KYT-01 and KYT-02.

KyteHaltGate

The gate is immutable, has no owner and holds no funds. It answers Open only for a fresh open row, and Unreadable while the oracle seat is unpaid. No live contract depends on it.

TimelockController

This is a standard OpenZeppelin TimelockController (full Sourcify match). Its configuration was reviewed on chain: the delay is 600 s, it administers itself, and the deployer holds no role. Its code was not re-analysed.

10. Checks that passed

✓ No admin path to escrowed collateralCollateral only ever moves to its seller, or to the option holder on exercise.
✓ Exits are never pausedCancel, exercise, expire, unstake, claim and split all work while paused. Pause only blocks new exposure.
✓ Reentrancy guardedEvery state-changing entry point uses nonReentrant (transient storage). State is set to its final value before any transfer.
✓ Fees capped in codePremium fee ≤ 10% and exercise fee ≤ 1%, fixed per position. Live: 3% / 0.1%.
✓ Fee-on-transfer tokens rejectedCollateral pulls and stakes check that the balance grew by exactly the amount transferred.
✓ NFT minting locked to the marketsOnly the market that owns an ID tag can mint or burn it. Markets are set once and wired correctly on chain.
✓ Fee split boundedShares must sum to 100% and stakers always get at least 20%.
✓ No just-in-time staking rewardsNew stake waits one epoch and is then locked for a full epoch.
✓ Router holds nothingRefunds go only to the caller. The Router's WETH and ETH balances are 0 at block 109,974,684.
✓ Deployer has no lingering powerThe deployer holds no timelock role, and OptionNFT market wiring is locked.
✓ Deployed code matches the sourceEvery contract in scope is a full Sourcify match (creation and runtime bytecode).

12. Limitations

This review cannot prove the absence of bugs. Static analysers find known patterns, and they can miss flaws in business logic, economic design, oracle assumptions and interactions between contracts. The manual review was carried out by the Kyte team, which is not independent of the code. Findings and configuration reflect the snapshot block above, and later transactions can change them. A third-party audit is recommended before significant growth in total value locked.
