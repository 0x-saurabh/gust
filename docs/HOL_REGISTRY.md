# Kyte on the HOL registry

[HOL (Hashgraph Online)](https://hol.org) runs a cross-registry directory of AI agents and MCP servers, searchable from
Claude, Cursor and other clients through their broker. Kyte lists its MCP server there as an HCS-11 profile with a
Universal Agent ID (UAID), so any HOL-connected agent can discover and call it.

## What is published

- Profile: `scripts/hol/kyte-profile.json`, generated by `scripts/hol/profile.mjs` from the live tool catalogue.
- Endpoint: `https://kyte.sh/api/mcp`, MCP streamable HTTP, no auth, read and prepare tools only.
- Ownership proof: DNS. A TXT record `_hedera.kyte.sh` whose value is Kyte's Hedera account id (HCS-11 `verification.type = dns`).

## Steps

1. MCP must be visible on production: `NEXT_PUBLIC_MCP_ENABLED` is `"true"` in render.yaml (the page and endpoint answer).
2. Hedera account and HOL key. Create or use a Hedera mainnet account for Kyte; sign in at https://hol.org/registry and create a
   Registry Broker API key in the billing portal. Base registration is in the free tier; the quote step confirms it.
3. DNS: add TXT `_hedera.kyte.sh` = `0.0.<account>`.
4. Generate and register:
   ```bash
   cd scripts/hol && pnpm install
   HEDERA_ACCOUNT_ID=0.0.xxxx node profile.mjs                 # from the local dev server; add the URL to read elsewhere
   REGISTRY_BROKER_API_KEY=… node register.mjs --quote          # should show 0 shortfall
   REGISTRY_BROKER_API_KEY=… node register.mjs --register       # prints the UAID, records it below
   ```
5. Optional: "verified and featured" at https://hol.org/registry/feature-your-agent, and the Plugins Registry listing at
   https://hol.org/plugins (scanner evidence plus owner verification).

Updates (new tools, description) go through `client.updateAgent(uaid, payload)`; regenerate the profile and run
`register.mjs --register` again once an update path is added.
